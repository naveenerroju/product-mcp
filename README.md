# product-mcp

A Model Context Protocol (MCP) server built with Spring Boot and Spring AI. It lets MCP clients such as Claude Desktop manage products by calling an existing REST service through a Feign client. The server communicates over **stdio**.

## Architecture

```
Claude Desktop  --stdio-->  product-mcp (this project)  --HTTP (Feign)-->  product-service (REST API)
```

**The actual REST API service lives here:** [naveenerroju/product-service](https://github.com/naveenerroju/product-service.git)

This project contains no product logic or database of its own. It only exposes tools that forward calls to `product-service`, so that service must be running for the tools to work.

## Tech stack

- Java 25
- Spring Boot 4.1.1
- Spring AI MCP Server Starter 2.0.1
- Spring Cloud OpenFeign
- Maven

## Project structure

```
src/main/java/com/github/product_mcp/
  ProductMcpApplication.java   # Entry point, enables Feign, registers tool callbacks
  ProductTools.java            # MCP tools (methods annotated with @Tool)
  client/
    ProductClient.java         # Feign client for product-service
    ProductDto.java            # DTO matching product-service's Product JSON
src/main/resources/
  application.properties       # MCP, stdio and product-service configuration
  logback-spring.xml           # Logging (stderr + file, never stdout)
```

## DTO

`ProductDto` mirrors the `Product` entity of `product-service`, without any JPA annotations:

```java
public record ProductDto(Long id, String name, double price) {}
```

| Field | Type | Notes |
|---|---|---|
| `id` | `Long` | Generated by product-service, send `null` when creating |
| `name` | `String` | Product name |
| `price` | `double` | Product price |

## Feign client

`ProductClient` maps to the endpoints of `product-service`:

| Method | Endpoint | Description |
|---|---|---|
| `getAll()` | `GET /products` | List all products |
| `create(ProductDto)` | `POST /products` | Create a product |

## MCP tools

| Tool | Parameters | Description |
|---|---|---|
| `getAllProducts` | none | List all products with id, name and price |
| `createProduct` | `name`, `price` | Create a new product (id is generated automatically) |

## Configuration

`application.properties`:

```properties
spring.application.name=product-mcp

# MCP server
spring.ai.mcp.server.name=product-mcp-server
spring.ai.mcp.server.version=0.0.1
spring.ai.mcp.server.type=sync

# STDIO transport
spring.ai.mcp.server.stdio=true
spring.main.web-application-type=none
spring.main.banner-mode=off

# REST service this MCP server calls
products.service.url=http://localhost:8080
```

Set `products.service.url` to wherever `product-service` is running.

### Important: stdout is reserved for the protocol

With stdio transport, anything written to stdout corrupts the MCP messages. So:

- Logging must go to **stderr** or a file (see `logback-spring.xml`).
- Do not use `System.out.println` anywhere in the code.
- Keep the Spring banner off.

## Build

```bash
mvn clean package
```

This produces the runnable jar at `target/product-mcp-server.jar`. Use this one, not `product-mcp-server.jar.original`.

## Run

1. Start `product-service` first (see its [repository](https://github.com/naveenerroju/product-service.git)).
2. Run the MCP server:

```bash
java -jar target/product-mcp-server.jar
```

It prints nothing and waits for MCP messages on stdin. Press `Ctrl+C` to stop.

## Add the MCP server to Claude Desktop

1. Build the jar (`mvn clean package`) and confirm `target/product-mcp-server.jar` exists.
2. In Claude Desktop, open **Settings → Developer → Edit Config**. This opens the exact `claude_desktop_config.json` the app uses.
3. Add the server under `mcpServers`:

```json
{
  "mcpServers": {
    "product-mcp-server": {
      "command": "C:\\Program Files\\Java\\jdk-25.0.4\\bin\\java.exe",
      "args": [
        "-jar",
        "D:\\peakcode workspace\\product-mcp\\target\\product-mcp-server.jar"
      ]
    }
  }
}
```

4. Save the file.
5. **Completely shut down Claude Desktop, then reopen it.** (see the warning below)
6. Open **Settings → Developer**. `product-mcp-server` should be listed as running, with its tools available.

### ⚠️ You must fully quit Claude Desktop

Closing the window is **not enough**. The app keeps running in the background and only reads `claude_desktop_config.json` at startup. The new config only took effect after completely shutting Claude down and reopening it:

- Quit from the system tray icon, or
- Open Task Manager and end **every** Claude process,
- Then start Claude Desktop again.

Do this every time you change the config or rebuild the jar.

### Tips

- Use the full path to `java.exe`. Claude Desktop may not see the same `PATH` as your terminal.
- The jar path in the config must match the file in `target/` exactly. If the name differs, Java fails with `Unable to access jarfile` and the server never shows up.

## Adding a new tool

1. If needed, add the endpoint to `ProductClient` (and fields to `ProductDto`).
2. Add a public method to `ProductTools` with the `@Tool` annotation:

```java
@Tool(description = "List all products with their id, name and price")
public List<ProductDto> getAllProducts() {
    return productClient.getAll();
}
```

3. Rebuild the jar and fully restart Claude Desktop.

## Troubleshooting

| Problem | Likely cause |
|---|---|
| Server not listed in Claude Desktop | Claude was not fully shut down, or wrong jar name or path |
| `Unable to access jarfile` | The jar path in the config doesn't exist |
| `No @Tool annotated methods found` | `ProductTools` has no `@Tool` methods, or wrong import |
| Server connects then drops | Something is writing to stdout (logs, banner, `System.out`) |
| Tool call fails with connection error | `product-service` isn't running or `products.service.url` is wrong |

Logs:

- Claude Desktop: `...\Claude\logs\mcp.log` and `mcp-server-product-mcp-server.log`
- App file log: `%USERPROFILE%\product-mcp\logs\product-mcp.log`
